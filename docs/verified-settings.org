#+TITLE: The Org configuration org-mcp is verified against

org-mcp reads and writes your Org files the way your Emacs does. It routes every
operation through Org's own functions — =org-todo=, =org-archive-subtree=,
=org-clock-clock-out=, =org-schedule=, =org-deadline=, =org-refile= — so the
settings that govern logging, blocking, drawers and done transitions are read by
Org at the moment it acts on your file. org-mcp never reads them itself, which
is why your configuration keeps working through it.

This page says where that claim is backed by tests, where org-mcp differs from
Org on purpose, and where nothing has been measured. For Emacs and package
versions see [[file:installation.org][Installing org-mcp]].

* Settings org-mcp honours and tests

Each of these is exercised at two or more values, with a different outcome
asserted for each. Changing them changes what org-mcp does, in the direction Org
documents.

| Setting | Values covered |
|---------+----------------|
| =org-use-tag-inheritance= | =t=, =nil=, a list of tags, a regexp |
| =org-tags-exclude-from-inheritance= | =nil=, a list of tags |
| =org-todo-keywords= | nine shapes: one and several sequences, =type= sets, fast-access keys, log cookies |
| =org-tag-alist= | plain lists, fast-access keys, mutually exclusive groups, group tags |
| =org-tag-persistent-alist= | =nil=, plain, fast-access keys, groups |
| =org-log-done= | =nil=, ='time=, ='note= |
| =org-log-into-drawer= | =t=, =nil=; a drawer named per node with =:LOG_INTO_DRAWER:= |
| =org-log-repeat= | =nil=, ='note= |
| =org-log-reschedule= | =nil=, ='note= |
| =org-log-redeadline= | =nil=, ='note= |
| =org-log-refile= | =nil=, ='time=, ='note= |
| =org-log-note-clock-out= | =t=, =nil= |
| =org-log-note-headings= | the default, and custom headings for a note and a clock-out |
| =org-clock-into-drawer= | =nil=, a named drawer, and the default =LOGBOOK= |
| =org-archive-location= | the default =_archive= file, a heading in the same file, and the =#+ARCHIVE:= line written and removed |
| =org-blocker-hook= | the child/sibling/parent blocker and the checkbox blocker, each with a vetoed and an unvetoed case |

A note written into Org's log machinery survives an org-mcp call: a half-typed
note in your Emacs is saved and restored around every write.

** In-buffer settings

A file's own =#+= lines are re-read after a write, so they stay in force and
override the session variables:

- =#+TODO:=, =#+SEQ_TODO:=, =#+TYP_TODO:= — the file's keywords win over
  =org-todo-keywords=. A rewrite that would silently retitle a heading is
  refused.
- =#+PRIORITIES:= — the file's range wins over =org-priority-highest= and its
  companions.
- =#+ARCHIVE:=, =#+CATEGORY:=, =#+FILETAGS:=, =#+TAGS:=, =#+STARTUP:=,
  =#+SETUPFILE:= — all read; the first five are writable one setting to a call.

Per-node overrides are honoured too: =:ARCHIVE:=, =:LOG_INTO_DRAWER:= and
=:NOBLOCKING:=.

* Settings org-mcp deliberately ignores

These are not gaps. org-mcp behaves differently on purpose, and a test pins each
one so the behaviour cannot drift back.

- =org-refile-targets=, =org-refile-use-outline-path= — =org-node-refile= takes
  the destination as an explicit parent link, so Org's target machinery never
  runs. A client names where a node goes; it does not search for it.
- =org-id-link-to-org-use-id=, =org-id-link-consider-parent-id=,
  =org-id-link-use-context=, =org-link-context-for-files= — the link in a
  response is built to one rule and is unaffected by how your Emacs stores
  links. In particular a read never creates an ID as a side effect.

* Settings nothing verifies

Org reads these itself, so its behaviour applies and they will very likely work.
What is missing is evidence, and two of them have a measured consequence.

- =org-use-property-inheritance= — property reads go through Org, and no test
  covers the inheriting case.
- =org-clock-continuously=, =org-mcp-clock-continuous-threshold= — continuous
  clock-in is live code and no test exercises it.
- =org-todo-state-tags-triggers= — a done transition rewrites the heading's tags
  and the response does not report it, so a later tag write can be refused for a
  change the client was never told about.
- =org-clock-out-switch-to-state= — the setting itself is covered. What is not:
  running it together with a blocker that vetoes the state change, where the
  veto is swallowed and the clock-out reports success.

org-mcp also answers for one Emacs. Org keeps its element caches in a store
shared by every Emacs using the same =org-persist-directory=, and a second Emacs
exiting can delete a file the first is reading back. When that happens while a
file is being opened, Org leaves the buffer half-configured and org-mcp answers
with an internal error rather than a refusal.
