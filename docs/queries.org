#+TITLE: Searching and GTD queries

This page answers how to search Org files with org-ql through org-mcp, and how
to wire up the three GTD query tools. The [[file:../README.org][README]] introduces the server
itself.

* Query tools

** org-query
- *Description:* Search Org files using org-ql query expressions. Supports querying by TODO state, tags, priority, deadlines, properties, and more
- *Parameters:*
  - =query= (string, required): org-ql query sexp as a string
  - =fields= (array of strings, or a string, optional): how much of each matching node to return; an array of field names, or the name of a configured list. It means here exactly what it means on =org-node-read=. See [[file:reading.org::*Asking for fields][Asking for fields]]
  - =files= (array of strings, optional): Files and directories to search, replacing the allowed files for this call. Directories are searched recursively. Defaults to all allowed files. See [[file:file-access.org::*Querying other files][Querying other files]]
- *Returns:* JSON object with a =children= array of the matching nodes (see [[file:reading.org::*The node][The node]]), the =total= count, and the =files_searched= count

Example:
#+begin_src json
# Request:
{
  "query": "(and (todo \"TODO\") (priority \"A\"))"
}

# Response:
{
  "children": [
    {
      "title": "Urgent task",
      "todo": "TODO",
      "priority": "C",
      "file": "/home/user/org/tasks.org",
      "level": 1,
      "link": "file:~/org/tasks.org::*Urgent task",
      "parent-priority": "A"
    }
  ],
  "total": 1,
  "files_searched": 3
}
#+end_src

A result is the node =org-node-read= returns for the same heading. Asked
nothing, a query leaves out =content= and =children= — a match list would read
every matched subtree to fill those — and carries the heading's Org property
drawer as =properties=. It leaves out the two digests as well, and a query that
names one hashes the region of every match (see [[file:reading.org::*The two digests][The two digests]]). =fields= is
how a call chooses otherwise, in either direction: naming =content= returns the
bodies, at that cost, and naming neither it nor =properties= returns neither.

Both tag fields come with a result asked nothing, so a client about to replace a
heading's tags works from =local_tags= without reading the heading again (see
[[file:reading.org::*The two tag fields][The two tag fields]]).

** query-inbox
- *Description:* Query inbox items using the configured GTD workflow
- *Parameters:* None
- *Returns:* Same as =org-query=, carrying the fields it carries unasked, sorted by =org-mcp-query-sort-fn= when configured
- *Configuration:* Requires =org-mcp-query-inbox-fn= to be set; tool is not registered when =nil=
- *Scope:* Always runs over the allowed files; a =files= parameter is refused

** query-next
- *Description:* Query next action items using the configured GTD workflow
- *Parameters:*
  - =tag= (string, optional): Tag string to filter results
- *Returns:* Same as =org-query=, carrying the fields it carries unasked, sorted by =org-mcp-query-sort-fn= when configured
- *Configuration:* Requires =org-mcp-query-next-fn= to be set; tool is not registered when =nil=
- *Scope:* Always runs over the allowed files; a =files= parameter is refused

** query-backlog
- *Description:* Query backlog items (projects and standalone actions) using the configured GTD workflow
- *Parameters:*
  - =tag= (string, optional): Tag string to filter results
- *Returns:* Same as =org-query=, carrying the fields it carries unasked, sorted by =org-mcp-query-sort-fn= when configured
- *Configuration:* Requires =org-mcp-query-backlog-fn= to be set; tool is not registered when =nil=
- *Scope:* Always runs over the allowed files; a =files= parameter is refused

* Configuring GTD Query Tools

The GTD query tools are opt-in.  Set the query functions and an optional sort comparator:

#+begin_src emacs-lisp
(setq org-mcp-query-inbox-fn   #'my-inbox-query
      org-mcp-query-backlog-fn #'my-backlog-query
      org-mcp-query-next-fn    #'my-next-actions-query
      org-mcp-query-sort-fn    #'my-rank-comparator)
#+end_src

Each query function should return an org-ql sexp.  =org-mcp-query-backlog-fn= and =org-mcp-query-next-fn= receive an optional tag-filter argument (an org-ql sexp or =nil=).  =org-mcp-query-sort-fn= is passed to =org-ql-select= as =:sort=.

* Configuring Extra Query Properties

=org-mcp-ql-extra-properties= lets you append computed values to every org-ql query result:

#+begin_src emacs-lisp
(setq org-mcp-ql-extra-properties
      '((parent-priority . my-parent-priority-fn)
        (rank . my-rank-fn)))
#+end_src

Each function is called at point with no arguments while a result is built.  Non-nil return values are appended to the node under the given key.

These are named by this setting rather than by a call, so they come with every
match whatever the call's =fields= asked for (see [[file:reading.org::*Asking for fields][Asking for fields]]).
